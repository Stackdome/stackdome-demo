Mirrored on Axernel

A URL goes in. A checked React component comes out.

Paste a page and name a part of it, like "pricing cards". An agent measures the live page, rebuilds that part in React and Tailwind v4, renders it, and compares it pixel by pixel with the original until it is close. We wrote the tools and the app. Axernel ran the agent.

For free

What Axernel gave us without being asked

Each point is something that happened during this build.

The output contract caught bad resultsWhen the agent submitted a malformed result, Axernel rejected it against our schema. The UI never had to guard against half a result.
Optional artifacts, honest caveatsAll ten files are required: false. A brand-mode run returns five files and a section run ten, with the same agent and no special cases.
Sessions pin the revisionWe published 11 revisions of the instructions. Old results kept opening, because each session stays on the revision it started with.
One model provider, two appsMirrored reused the provider WalkThroughPark created. Its key is write-only, so this app never saw or stored it.
Cost per runEvery run reports tokens and dollars. That is how a whole build, failed runs included, stayed at about $0.35.
A platform change cost the app one lineImage input landed in Axernel as a 2-commit branch. The app needed inputModalities: ["text","image"] and one sentence in the instructions.
The platform change this app caused

Letting the model see its own screenshots

Before

Axernel told the harness the model was text only. The agent made screenshots and diffs, and none of them ever reached the model.

After

The model provider declares what it accepts. The harness passes that to OpenCode. In the next run the agent opened 4 screenshots by itself.

Branch feat/model-input-modalities (local, not pushed yet):

  • optional inputModalities on model providers
  • one migration: a nullable jsonb column
  • the harness writes attachment and modalities into the OpenCode config only when they are declared
  • with nothing declared, the generated config is byte-identical to before
Rough edges, for the platform team
  1. The event stream can die in the middle of a run: harness_stream_unavailable, "Event history is unavailable or incomplete". The run itself goes on and finishes.
  2. The model spec had no modalities. Fixed on the branch above, but the console has no field for it yet.
  3. Usage numbers are sometimes incomplete. One 25 minute run reported a cost we could not trust.
  4. There is no platform-published default image or template with a browser in it. Every browser app starts by building one.
  5. creation_unknown gives no hint that the sandbox provider cannot be reached. We lost hours to a network problem that looked like a platform bug.
  6. The harness drops the image's ENV. Every tool has to default its own paths.
  7. Image pushes are slow, so Dockerfile layer order matters a lot: heavy and stable first, your scripts last.
  8. Licensed web fonts end up inlined in preview.html. Fine for a private check, not for sharing.
